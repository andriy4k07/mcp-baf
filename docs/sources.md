[← Назад до змісту](README.md)

Початкові специфікації — документи `01`–`07` з локального `mcp-baf-research`, дослідження від 2026-10-01. Сам дослідницький каталог не потрібен для встановлення mcp-baf.

У research ліцензію BSL Language Server помилково позначено Apache-2.0. В документації mcp-baf використано LGPL-3.0-or-later за актуальним заголовком офіційного джерела. У поточній реалізації BSL Language Server не є залежністю: базові перевірки та форматування виконуються власним Python-кодом.

Офіційна довідка платформи не включена до пакета. Користувач надає свої `.hbk`-файли; тестова HBK-фікстура містить лише власні короткі тестові сторінки. Docker/Qdrant і embedding-код onec-help-mcp не використовуються.

## Кандидати діагностик `bsl_analyze`

Станом на issue #54 у `bsl_native` десять перевірок (`local-tools.md`): вісім базових плюс `ReservedDeclarationName` (#4904) і `LatinAndCyrillicSymbolInWord` (#4900). Нижче — оцінка кандидатів з [1c-syntax/bsl-language-server](https://github.com/1c-syntax/bsl-language-server); його код не переноситься (LGPL-3.0-or-later), запозичуються лише опис поведінки й тестові сценарії. Стан апстриму перевірено через GitHub API 2026-11-11.

| Кандидат | Що перевіряє | Стан апстриму | Вердикт для `bsl_native` | Рекомендація |
|---|---|---|---|---|
| [#4905](https://github.com/1c-syntax/bsl-language-server/issues/4905) | Виклик без отримувача, що не розв'язується ні в методи модуля, ні в глобальний контекст платформи (приклад: `Абс(Значение)`) | open, без коментарів | Лексер і парсер достатні (виклик без отримувача видно як `call` з простим ім'ям). **Ризик хибних спрацювань:** немає повного переліку глобальних функцій за версіями платформи й глобальних експортів конфігурації — фрагмент їх не бачить | відкладено |
| [#4904](https://github.com/1c-syntax/bsl-language-server/issues/4904) | Оголошення `Функция Найти(...)`: парсер приймає, компілятор 8.3.27 відхиляє («Ожидается имя функции») | open, без коментарів | Лексер і парсер достатні: оголошення методу відрізняється від виклику `Массив.Найти()` (вузол `member`). Потрібен курований перелік зарезервованих імен для цільової версії платформи | реалізовано в #54 як `ReservedDeclarationName` (`RESERVED_DECLARATION_NAMES`) |
| [#4900](https://github.com/1c-syntax/bsl-language-server/issues/4900) | `LatinAndCyrillicSymbolInWord`: латиниця всередині слова в автозгенерованих іменах обробників полів (`АвтоупаковкаЗаказовWBПриИзменении`) | open, мітка `type/FP` | Лексер достатній (ідентифікатори з позиціями, Unicode). **Ризик хибних спрацювань:** у фрагменті немає метаданих, тому обробник розпізнається лише евристично за суфіксом події форми | реалізовано в #54 як `LatinAndCyrillicSymbolInWord` з придушенням за `FORM_EVENT_SUFFIXES` |
| [#4862](https://github.com/1c-syntax/bsl-language-server/issues/4862) | `VirtualTableCallWithoutParameters`: таблична частина з іменем «Остатки»/«Обороты» приймається за віртуальну таблицю регістру | open, мітка `type/FP`; виправлення зроблено в граматиці `bsl-parser` | **Потрібна робота над граматикою:** SDBL не розбирається, текст запиту — непрозорий рядковий літерал; без виду об'єкта метаданих перевірка неможлива | відкладено |

Примітки до статусів:

- **#4862.** PR [#4913](https://github.com/1c-syntax/bsl-language-server/pull/4913) закрито 2026-11-07 **без влиття** — він дублював #4883 і зачіпав діагностики замість граматики. Виправлення перенесено в граматику: [1c-syntax/bsl-parser#437](https://github.com/1c-syntax/bsl-parser/pull/437) влито 2026-11-10, діагностики BSL LS при цьому не змінювались. Сам issue #4862 лишається відкритим. Отже «виправлено в bsl-ls» — некоректне формулювання: виправлено в парсері запитів.
- **#4904.** Ідеться саме про ім'я оголошення, а не про виклик: `Массив.Найти(...)`, `Справочники.НайтиПоКоду(...)`, `ТаблицаЗначений.НайтиСтроки(...)` лишаються допустимими й не повинні давати діагностику.
- **#4905.** Довідник `bsl/_functions_data.py` містить 180 записів і `Абс` серед них немає, що збігається з прикладом з issue, але цей перелік — вибірка для `bsl_syntax_help`, а не повний глобальний контекст платформи. Перевірка на такій вибірці дала б хибні спрацювання на кожній функції поза нею.
- **#4900.** Імена обробників генерує платформа з імені реквізита й назви події, тому іноземне слово опиняється в середині слова. Для фрагмента без метаданих потрібен явний перелік суфіксів подій; інакше діагностика зачіпає звичайні змішані імена.

Закриті трейд-пункти моніторингу: [#4568](https://github.com/1c-syntax/bsl-language-server/pull/4568) і [#4548](https://github.com/1c-syntax/bsl-language-server/pull/4548) закрито 2026-10-28 **як замінені**, а не влиті: їхню поведінку об'єднує `MethodCallUnavailable` у [#4871](https://github.com/1c-syntax/bsl-language-server/pull/4871), який станом на 2026-11-11 ще відкритий. Пункт моніторингу знято; у `bsl_native` ці перевірки не плануються (потрібні метадані спільного модуля й контексти компіляції).
