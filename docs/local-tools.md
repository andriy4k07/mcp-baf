# Локальна довідка та BSL

[← Назад до змісту](README.md)

Локальні інструменти працюють на машині MCP-сервера й не потребують HTTP-з'єднання з BAF. `bsl_syntax_help`, `bsl_analyze` і `bsl_format` доступні завжди; HBK-довідка вмикається через `--help-dir`.

## Довідка платформи

Передайте каталог із `.hbk`-файлами, які постачаються з вашою платформою:

```sh
mcp-baf --help-dir /path/to/platform-help/8.3.14 --cache-dir /path/to/cache
```

Сервер рекурсивно читає `.hbk`, отримує HTML із `FileStorage` і будує SQLite FTS5 у фоновому потоці. До готовності повертає повідомлення про індексацію. Пошкоджений `.hbk` пропускається із записом у `server.log`, решта файлів індексується. Відсутній каталог, порожній набір файлів або відсутність жодної придатної сторінки дають явну помилку доступності з назвою файлу; це не порожній результат пошуку.

Пошук префіксний: слово збігається з початком імені та з частинами CamelCase-назви (`Найти` знаходить `СтрНайти`). Слова запиту поєднуються через AND; якщо так нічого не знайдено, пошук повторюється через OR.

Кеш — `help-<hash>.sqlite` у каталозі кешу, хеш залежить від шляху довідки. Незмінні файли повторно не парсяться; при зміні набору, mtime чи розміру HBK індекс перебудовується атомарно. `--reindex` примусово перебудовує його. Пошкоджений SQLite-кеш відновлюється автоматично.

Приклади аргументів MCP:

```json
{"query":"HTTPConnection","limit":10,"section":"types"}
```

```json
{"name":"HTTPСоединение"}
```

Перший приклад — `search_platform_help`, другий — `get_platform_element`. Назви російською та англійською шукаються за заголовками сторінок і вмістом; для вбудованих функцій також застосовуються BSL-синоніми. Пошук — лексичний BM25, не семантичний RAG.

`section` може бути порожнім або `functions`, `types`, `operators`, `vtables`, `skd`. Класифікація евристична: якщо потрібного результату немає, повторіть пошук без фільтра. Картка зберігає синтаксис і приклади з HTML; відсутні у джерелі відомості сервер не вигадує.

Версія визначається з каталогу формату `8.x.y`; якщо такого компонента шляху немає, показується «не вказана». Це версія наданого джерела, а не перевірка сумісності з базою. Для однакових назв у різних HBK `get_platform_element` повертає кандидатів; передайте `source` з вибраного результату разом із `name`.

Джерело адаптованого HBK-парсера — [rzateev/onec-help-mcp](https://github.com/rzateev/onec-help-mcp), деталі й атрибуція — [sources.md](sources.md).

## Аналіз та форматування BSL

`bsl_analyze` і `bsl_format` використовують власний Python-лексер та базовий парсер. Java, JAR, Docker та додаткові пакети не потрібні. Це обмежені перевірки текстового фрагмента, а не повний BSL Language Server чи компілятор платформи.

Приклад `bsl_analyze`:

```json
{"src":"Процедура Тест()\n    Перем А;\nКонецПроцедуры","levels":["error","warning"],"limit":50}
```

`src` — текст до 2 MiB, не шлях до файла. `levels`: `error`, `warning`, `information`, `hint`; типово вибираються `error` і `warning`. `diagnostic_codes` фільтрує вибрані коди. `limit` — 1–500, типово 50. Рядки та колонки починаються з 1. Реалізовано вісім перевірок:

| Код | Рівень | Що перевіряється |
|---|---|---|
| `ParseError` | error | Літерали, вирази, роздільники, парні конструкції, розміщення переходів і структурні пари директив |
| `DuplicateParameter` | error | Повторні імена параметрів без урахування регістру |
| `DuplicateVariable` | error | Повторні явні локальні оголошення, включно зі збігом з параметром |
| `UnusedLocalVariable` | warning | Явно оголошена локальна змінна не читається в межах методу |
| `UnreachableCode` | warning | Оператор у тому самому блоці після безумовного переходу |
| `EmptyExcept` | warning | Порожній обробник винятку |
| `TrailingWhitespace` | information | Кінцеві пробіли поза рядковими літералами |
| `LineLength` | information | Рядок довший за 120 символів |

Підтримуються російські й англійські ключові слова, процедури/функції, параметри, оголошення, присвоєння, виклики, доступ до полів/індексів, умовні вирази, цикли, `Если`, `Попытка`, переходи, обробники подій, `Асинх`/`Ждать`, коментарі та багаторядкові рядки з `|` (між продовженнями допускаються порожні рядки й коментарі), сусідні рядкові літерали, дати з роздільниками та BOM на початку модуля. Обмеження — 2 MiB тексту і вкладеність до 100; перевищення дає явну помилку.

Умови препроцесора не обчислюються: парсер розглядає текст усіх гілок разом, тому умовні альтернативні заголовки чи частини конструкцій можуть дати `ParseError`. Перевірки повторних локальних оголошень та невикористаних змінних вимикаються за наявності умовних директив. Оператор одразу після директиви препроцесора не вважається недосяжним: `Возврат` усередині `#Если` не дає `UnreachableCode` для коду після `#КонецЕсли`. Невикористані змінні також не перевіряються для методів із `Выполнить` та для фрагментів із `Вычислить`/`Eval`. Читання імен у коментарях, рядках і назвах властивостей не враховується. Типи, доступність методів платформи, метадані, клієнтський/серверний контекст, повний потік керування й семантика запитів не перевіряються. Відсутність діагностик не підтверджує компіляцію.

`bsl_format` приймає той самий `src` і повертає код у Markdown. Вирівнює відступи по 4 пробіли та прибирає кінцеві пробіли поза коментарями й багаторядковими літералами. Зберігає регістр, проміжки між токенами, текст коментарів, літерали, стиль LF/CRLF і наявність фінального переносу. Продовження багаторядкових рядків зберігаються разом з початковими відступами. Директивам не додає окремих рівнів відступу; рядки-продовження багаторядкового оператора отримують один додатковий рівень. Перед поверненням повторна токенізація перевіряє незмінність токенів. Форматування відхиляється лише за `ParseError`; повторні імена параметрів чи змінних йому не заважають.

Код обробляється у пам'яті в Python-потоці; файли з кодом та зовнішні процеси не створюються. Файли користувача не читаються й не переписуються. В аудит потрапляють розмір коду та фільтри, без коду й діагностик. Непідтримувана конструкція дає помилку базового парсера, а не висновок про помилку компілятора платформи.
