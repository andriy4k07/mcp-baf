# Архітектура

[← Назад до змісту](README.md)

mcp-baf — самостійний MCP-сервер для читання BAF, локального пошуку довідки й аналізу BSL. Дані бізнес-об'єктів не записуються; форматування BSL не змінює файли користувача. Походження реалізації та ідей описано в [sources.md](sources.md).

```text
AI-клієнт ← stdio → AccessMCP (Python) → HTTP → розширення MCPService /hs/mcp-baf
                         ├─ dumpindex: локальний код → SQLite FTS5 (--dump)
                         ├─ helpindex: локальні HBK → SQLite FTS5 (--help-dir)
                         └─ bsl_native: текст → Python-парсер → діагностики / відступи
```

## Реєстрація та доступ

`__main__.py` запускає інсталятор з `--install` або створює сервер на stdio. `server.create_server` реєструє 13 базових інструментів; локальні опції додають до трьох. Усі повертають готовий Markdown і мають `readOnlyHint=True`.

`AccessMCP` — підклас `MCPServer` офіційного MCP SDK 2.x, який перевизначає `list_tools` та `call_tool` і передає контекст запиту SDK. `GET /capabilities` віддає дозволені HTTP-методи за правами HTTP-користувача. Таблиця `access.TOOL_METHODS` зіставляє інструменти з методами; локальні інструменти не залежать від цієї перевірки.

Список прав кешується на 30 секунд, перед HTTP-викликом перевіряється заново. Недоступність або некоректна відповідь `/capabilities` закриває доступ до HTTP-інструментів. Приховування списку доповнено відмовою прямого виклику й перевіркою права в кожному HTTP-обробнику. Привілейований режим для цього доступу не використовується: у такому режимі методи відмовляють у перевірці.

`MCP_ОсновнаяРоль` надає використання методів сервісу, але не права читання бізнес-об'єктів. Для диференційованого доступу налаштовують права методів без цієї повної ролі. Нових бізнес-ролей і контейнерів обробок немає. Дані запитів і пошуку залишаються в межах прав/RLS HTTP-користувача.

`МетодДоступен` знаходить сервіс, шаблон URL та метод, після чого перевіряє
`ПравоДоступа("Использование", Метод)`. Роль містить 13 прав `Use` на кінцеві
методи `HTTPService.MCPService.URLTemplate.<Шаблон>.Method.<Метод>`.
Сервіс і шаблон не додаються як окремі умови допуску. У разі відмови
`/capabilities` повертає 403 і технічний код `reason`, щоб розрізняти
відсутнє право, відсутні метадані, привілейований режим та помилку перевірки.

## HTTP-контракти

Наявні маршрути метаданих, форм, запитів, конфігурації й журналу збережено. Нові маршрути:

| Маршрут | Контракт |
|---|---|
| GET `/capabilities` | `{methods:["metadata.GET", ...]}`; лише перевірка використання HTTP-методів |
| POST `/refs` | Тип + GUID, області, ліміти й бюджет → `{hits, skipped_names, timeout_exceeded, truncated}` |
| POST `/object-link` | `{mode, kind, ref}` → `{found, kind, ref, presentation, link}`; Python розбирає підтримуване посилання перед запитом |
| POST `/metadata-rights` | `{metadata_object, user_name, rights, roles}` → `{rights:[{right,subject,allowed}], notes}`; `allowed=null` означає недоступну перевірку |

Пошук посилань обходить поля метаданих з цільовим типом, перевіряє імена та право читання батьківського об'єкта й виконує параметризовані `SELECT РАЗРЕШЕННЫЕ`. Права полів і RLS перевіряє платформа під час запиту; перевірка `ПравоДоступа("Чтение", Поле)` для вкладених метаданих не використовується, бо на старих платформах вона може викидати виняток для доступного поля. Запит без доступу до потрібного поля чи ключа цілком потрапляє до пропусків. Імена таблиць/полів беруться лише з метаданих; GUID перетворюється на посилання платформи й передається параметром. Для записів регістрів повертаються ключові поля. Частковість, пропуски й досягнуті ліміти показуються явно. Бюджет перевіряється між запитами, не перериває активний запит до СУБД.

Навігація повертає внутрішнє `e1cib/data/...` поточної бази, а не вигадану адресу веб-публікації. Python приймає також URL публікації з внутрішнім фрагментом, але не завантажує його. Сам тип/GUID перевіряється в поточній базі. Права об'єкта не використовуються для висновків про RLS.

Нові пошукові SELECT-запити використовують `РАЗРЕШЕННЫЕ` для відбору доступних записів: [пояснення платформи про RLS](https://kb.1ci.com/1C_Enterprise_Platform/FAQ/Development/Standards/Record-_and_field-level_access_restrictions/?language=en). Перевірка іншого користувача передає його безпосередньо третім параметром `ПравоДоступа`, який підтримує користувача або роль: [офіційні примітки платформи](https://1c-dn.com/library/v8update_2569827938_changes_that_require_modification_of_configuration_and_administrative_settings/).

## Аудит і HTTP-клієнт

Кожен інструмент використовує `tools.common.traced_text`: успіх або помилка з `trace_id` та тривалістю. Перевірка доступу й виконання HTTP-інструмента успадковують цей trace. Відмови прямого виклику аудіюються без бізнес-аргументів; успішна авторизація не створює додаткової події `tool.call`.

`OneCClient` використовує httpx, Basic auth, `Connection: close`, потокове читання з лімітом розміру й таймаут. Кожен HTTP-запит має окрему `one_c.http`-подію без успішного тіла відповіді. `audit.log` та операційний `server.log` розділено; stderr лише для ERROR. Деталі — [logging-and-audit.md](logging-and-audit.md).

## Локальні компоненти

Dump-індекс має інкрементальне оновлення модулів та режими smart/regex/exact; див. [search-and-index.md](search-and-index.md). HBK-індекс будується у фоні, кешується за маніфестом і перебудовується атомарно. З'єднання SQLite захищено lock; читання довідки не блокує async-цикл MCP.

`bsl_native` містить власний двомовний лексер, базовий рекурсивний парсер і вісім перевірок. Аналіз та форматування виконуються у Python-потоці без зовнішніх процесів і тимчасових файлів із кодом. Форматер змінює відступи та перевіряє збереження всіх токенів. Оригінальні файли не змінюються, код і діагностики не записуються в аудит. Деталі — [local-tools.md](local-tools.md).

## Розширення та оновлення

XML-вихідники `extension_src/` постачаються в Python-пакеті. `installer.py` копіює їх у тимчасовий каталог, локалізує синоніми (`--lang ua|ru`), патчить формат XML і режим сумісності під платформу та завантажує через DESIGNER `/LoadConfigFromFiles` з `/UpdateDBCfg`. Мінімальна платформа інсталятора — 8.3.10.

Версія пакета — **0.2.0**, розширення — **0.5.5**. Коментар/відповідь `/version`, `Configuration.xml` і `EXPECTED_EXTENSION_VERSION` узгоджені; `ConfigDumpInfo.xml` містить маршрути та їхні UUID. Стартова перевірка версії повідомляє про розбіжність; перевірка capabilities окремо блокує HTTP-інструменти, якщо її немає.

Розширення на живу базу встановлює власник. Нові BSL-обробники, права, посилання та регістри потребують live-перевірки; Python-тести перевіряють клієнтські й XML-контракти. Діагностика документів із тестовим проведенням відкладена. Запис у базу залишається відповідальністю [baf-write-mcp](https://github.com/andriy4k07/baf-write-mcp).
